# ADR-007: 用真实进程端到端脚本作为交付门槛，而非只靠单元测试

## Status

Accepted (2026-09-22)

## Background

「单测全绿」与「系统真的能跑起来」之间存在巨大鸿沟。常见的失败包括：
应用启动即崩溃、端口冲突、路由未注册、SSE 帧格式错误、
错误处理路径从未被执行过。这些都不在单元测试的覆盖范围内。

## Decision

交付物必须包含 `scripts/e2e.py`：

1. 用子进程真实拉起服务（不是 TestClient，是独立进程）
2. 轮询 `/api/health` 直到 200，超时则**打印子进程 stderr 后失败**，不静默跳过
3. 覆盖成功流（摄入 / 检索 / 三种模式 / 问答 / SSE / trace / metrics）
4. 覆盖错误流（404 / 422 / 删除 / 计数递减）
5. `finally` 中强制清理进程（Windows 用 `taskkill /pid X /t /f`），否则端口泄漏会让后续运行失败
6. 汇总「通过 N / 失败 M」，非 0 退出码

并且把它接入 `scripts/verify.py`，与 lint / type-check / 单测 / 评测形成完整门禁。

## Consequences

正面：
- 交付前能证明「服务真的起来了」，而不是「代码看起来没问题」
- 错误流被真实执行过，不是纸面契约
- 端口泄漏问题被消除，脚本可反复运行

负面：
- 比纯单测慢（起进程、等健康检查）
- 需要小心处理进程生命周期，否则会留下僵尸进程
