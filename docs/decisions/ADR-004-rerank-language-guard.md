# ADR-004: 重排默认关闭，且必须加语言守卫

## Status

Accepted (2026-09-22)

## Background

交叉编码器（cross-encoder）重排在理想条件下能提升排序质量，但存在一个代价高昂的陷阱：

**当重排模型的训练语言与查询语言不一致时 —— 最常见的是英文 reranker 处理中文查询 ——
它给出的分数接近随机。而它的输出会直接覆盖融合排序里的所有其他信号，
于是「启用重排」反而比「不重排」更差。**

实测：一组中文查询的 top-1 命中数从 11/12 掉到 4/12。

这个坑之所以危险，是因为它在英文评测集上完全看不出来。团队在英文基准上验证收益、
上线到中文业务后指标悄悄劣化，等到业务反馈时已过去数周，排查时还容易误判成
嵌入模型不好或切片不合适，从而白白重构整条检索链路。

## Decision

1. 默认**不启用**重排（`RERANK=off`）
2. 即便启用，也必须经过 `GuardedReranker`：
   查询以中文为主且重排器未在中文语料上训练时，自动旁路降级为恒等/覆盖重排
3. 降级决策写入 `last_decision` 并进入追踪数据，不做沉默降级
4. 提供零依赖的 `CoverageReranker` 作为重型模型不可用时的高质量替代

## Consequences

正面：
- 规避了最昂贵的一类线上事故（排序静默劣化）
- 默认配置下的行为是确定的、可预测的
- 降级有据可查，出现质量问题时能快速归因

负面：
- 放弃了在合适场景（英文查询 + 英文 CE）下的排序增益
- 守卫依赖「查询是否为中文主导」的启发式判断，中英混排极端情况可能误判
